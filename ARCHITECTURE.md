# Смета 3D — устройство кода

Исходников автора нет, поэтому код восстановлен из собранной версии: он отформатирован по строкам, но имена функций и переменных остались короткими (`en`, `ca`, `l`). Эта карта помогает в нём ориентироваться. Номера строк приблизительные — ищите по имени функции (`function en(`).

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Разметка страницы: шапка, блоки «Модель», «Печать», «Заказ», смета, «Моделирование», «Настройки мастерской». Скрипты и стили подключены отдельно |
| `styles.css` | Все стили, светлая и тёмная тема |
| `app.js` | Вся логика калькулятора |
| `rates.dat` | Опубликованные ставки мастерской (JSON, XOR с ключом `smeta3d·rates`, base64). Сайт читает его с GitHub, если не вышло — локальную копию |
| `plugin.html`, `download/smeta3d_orca.py` | Страница и плагин для OrcaSlicer |
| `tools/version.py` | Метки версий `app.js?v=…`, `styles.css?v=…` в `index.html`. **Запускать после каждой правки `app.js` или `styles.css`**, иначе автотест не пройдёт |
| `vendor/` | Локальные копии three.js и JSZip на случай недоступности CDN |
| `tests/`, `.github/workflows/prices.yml` | Автопроверка цен на GitHub (см. `tests/README.md`) |

## Состояние

| Имя | Что это |
|---|---|
| `l` | Всё текущее состояние: `l.tech`, `l.sel` (выбранные принтер и материал по технологиям), `l.slicer`, `l.sla`, `l.sls`, `l.part` (количество, название…), `l.money` (ставки, налоги, контакты, шаблон КП, моделирование), `l.printers`, `l.materials`, `l.basket` (детали заказа), `l.mode`, `l.access` |
| `K` | Опубликованные ставки из `rates.dat` — база, поверх которой лежат локальные правки |
| `nt` | Обёртка над `localStorage` с префиксом `fdmcalc.v1.` (`nt.get`, `nt.set`, `nt.del`) |
| `H` | Текущая модель: `H.pos` (треугольники), `H.st` (габариты, объём, слои), `H.ver` |
| `lt` | Оценка печати по модели для текущих настроек |
| `rn` | Последний результат расчёта сметы |

## Расчёт цены

| Функция | Что делает |
|---|---|
| `ua()` | Оценка по модели: FDM — `ss()`, фотополимер — `is()` |
| `ss()` | FDM: вес и время по слоям, стенкам, заполнению, поддержкам |
| `is()` | SLA/DLP/LCD: смола, время слоёв |
| `os()` | SLS: запуски, высота сборки, порошок |
| `wn()` | Сколько деталей помещается на стол |
| `Pe()` | Позиция заказа из текущей формы (вес, время, принтер, материал, количество) |
| `ca(item, money)` | Себестоимость одной позиции: материал, станок, энергия, работа, брак |
| `en(items, money)` | Смета заказа: общие столы, наценка, опт, минимум, налог, НДС, срок |
| `loPlates()` | Раскладка позиций одной технологии на общие столы |
| `loFloor()` | Итог на пороге опта не меньше, чем на 1 шт меньше |
| `Wi()`, `loReady()` | План и дата готовности с учётом рабочих часов и праздников |
| `Ki()` | Доля ночного тарифа |

| Группа | Функции |
|---|---|
| Детали заказа | `loNewPart`, `loSelect`, `loLoad`, `loDup`, `loDel`, `loSyncCur`, `loStoreCur` |
| Автоподбор принтера | `loPick` (только Простой режим) |
| Моделирование | `loCadS`, `loCadCalc`, `loCadRender`, `loCadInit`, `loModSettings` |
| Заявки и печать | `loLead`, `loLeadGo`, `loKp` |
| Оформленное КП (PDF) | `loKpHtml` (документ), `loKpPdf` (печать), `loSnapPng` (снимок модели) |
| Логотип и фирменный цвет | `loBrand`, `loBrandInit`, `loLogo`, `loHS` (цвет → оттенок) |

## Тяжёлые модели в фоновом потоке

Для моделей от 100 тыс. треугольников статистика (`vn`), нарезка на слои (`Mn`, `as`, `Vi`, `Ui`) и поиск плоских граней (`Hs`) считаются в Web Worker. Отдельного файла для него нет: `loWorker()` собирает код потока из тех же функций (`${vn}`, `${Mn}`…), поэтому формулы всегда одни и те же. Готовые кэши нарезки (`_ras`, `_fw`, `_fs`) возвращаются вместе со статистикой, и первый пересчёт цены берёт их из кэша.

Если поток не запустился или упал, всё считается по-старому в основном потоке. При правке `vn`, `Mn`, `as`, `Vi`, `Ui`, `ia`, `es`, `sa`, `Hs` не добавляйте в них обращения к другим функциям или состоянию `l` — в фоновом потоке их нет.
